# Chronicle Advanced — Instructor prep

Video: [Instructor-Explainer.mp4](../Instructor-Explainer.mp4) · Runtime: 00:07:40.542

Narration: **Microsoft Foundry (gpt-audio-1.5-2, alloy)** (mode: `foundry`).

Times below are playback positions. Lab allocations refer to the separate 90-minute workshop. App views show local fixtures, not a live Foundry run.

## Lab 00 — Baseline (8 workshop minutes)

**00:00:00 · Stage a story the room can finish**

Before learners arrive, open the starter directly in VS Code. Stage a small session with a decision and a follow-up. Ask the room to predict what the next developer would need; return to their answers at the end.

**00:00:47 · Start the clock with evidence**

Use the first eight minutes for three checks: the workspace root, a current Node runtime and a passing suite. Select Agent mode and a frontier model. Distribute the five connection values privately, not in the projected chat.

## Lab 01 — Role agents (17 workshop minutes)

**00:01:27 · Make delegation visible**

In the next seventeen minutes, project the customizations view. Ask someone to identify the one role that should appear in the chat picker. Then show why the lead has an agent tool but no edit or execute permission.

**00:02:13 · Rescue a missing worker**

If the team does not appear, check which folder VS Code opened and inspect the frontmatter warnings. If a security worker proposes a patch, ask who actually has permission to edit. The reviewer should return a finding with a file and line.

## Lab 02 — Reusable skills (15 workshop minutes)

**00:02:29 · Teach the difference with a swap test**

For lab two, reserve ten of fifteen minutes for skill creation, three for attachment and two for discovery. Ask: if we replace the docs playbook, can the writer suddenly run a terminal? No. Permissions belong to the agent.

**00:02:53 · Keep the workshop moving**

A missing skill usually warrants a spelling check before another generation attempt. Compare the directory, frontmatter name and worker reference side by side. Have everyone switch to Chronicle Orchestrator before dispatching the first feature.

## Lab 03 — Connectivity (15 workshop minutes)

**00:03:49 · Separate the private entry from the public demo**

In lab three, allow ten minutes for implementation and five for the live test. Project the fixture dialog for orientation, then blank the projector for real entry. Ask learners what the public settings endpoint should reveal about the secret: only whether it exists.

**00:04:07 · Triage by the last completed exchange**

If token acquisition fails, check the tenant, client and secret privately. If the token succeeds but Foundry forbids the call, check the project target and Foundry Agent Consumer assignment. Timebox the detour; label a mock-only result honestly.

## Lab 04 — Session handoff (18 workshop minutes)

**00:04:30 · Rehearse the moment of choice**

In the eighteen-minute handoff lab, have a learner choose a session they are permitted to send. Ask for one known fact and one open task before clicking Create session summary. Those are your acceptance criteria, not the word count.

**00:04:47 · Force the interesting branch locally**

Demonstrate the multi-chunk path with a deterministic test. The expected calls are a digest for each part and one final synthesis. Ask why a short session skips the extra round trips. Keep the live example small enough to finish.

**00:05:59 · When the popup is blocked**

Show how the log differs from the Markdown output. If the popup is blocked, use the inline fallback. If a job fails, inspect its last phase rather than rerunning blindly. Never ask someone to paste a token or a raw credential file.

## Lab 05 — Browser release (17 workshop minutes)

**00:07:05 · Protect the final seventeen minutes**

In lab five, let the tester draft checks while the developer renders the icon, but run them after the asset lands. If time slips, cut the desktop tour to one diagram. Do not skip the direct PNG request or the regression suite.

**00:07:23 · Ask for three receipts**

For the closing recap, ask where the desktop server would run, where its credentials would live, and what ships today. The answers are a separate utility process, writable per-user storage outside the installer, and the package-free browser release.
